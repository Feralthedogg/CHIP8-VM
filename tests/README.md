# Tests

The test harness loads the linked PE executable into Unicorn and calls its actual
x86-64 functions. It does not replace CHIP-8 instructions with a Python
interpreter. Python 3.10 or newer, MinGW-w64 GCC/binutils, and the packages in
`requirements.txt` are required.

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r tests/requirements.txt
make test PYTHON=python
```

Use `make test-core` for the six offline regression tests, or `make test-roms`
for the seven ROM-level checks. All targets build `chip8.exe` first. Override
`CC`, `NM`, or `PYTHON` on the Make command line for a different toolchain.
`CHIP8_EXE=/absolute/path/to/chip8.exe` selects another binary for comparisons.
The executable must retain its COFF symbol table, as normal `make` builds do.

## Regression coverage

- `Cxkk`: all 16 destination registers, four masks, a sequence of random bytes,
  and unchanged neighboring registers.
- `Fx33`: seven values at an ordinary address and at `0xFFD`, `0xFFE`, and
  `0xFFF`; only the three wrapped RAM destinations and advanced PC may change.
- `MM_WOM_DONE`: empty and 160-sample completed buffers; preservation of the
  caller's eight nonvolatile general registers; correct requeue arguments and
  silent PCM generation. The `waveOutWrite` stub checks stack alignment and
  deliberately overwrites volatile registers and its 32-byte home space.
- `Fx0A`: timers and PC while waiting, matching versus unrelated releases,
  and a key that was already held.

The random, BCD-boundary, and callback-preservation regressions fail against
the original `745b979bc364e9b5669248b877b3963fd0c1ea3f` executable and pass with
the fixes.

## Independent ROM inputs

`timendus.json` pins the upstream repository to commit
`742e9eac9f5d44466c1c9d83fcaa8158c6683cb1` and lists SHA-256 checksums for every
downloaded ROM and reference PNG. The first ROM test run fetches them from
`raw.githubusercontent.com` into `tests/.cache/timendus/`. Cached files are also
checksum-verified on subsequent runs. No external input is downloaded during the
normal VM build. Network errors and checksum mismatches fail the tests.

These fixtures come from [Timendus/chip8-test-suite](https://github.com/Timendus/chip8-test-suite)
and retain its [GPL-3.0 license](https://github.com/Timendus/chip8-test-suite/blob/742e9eac9f5d44466c1c9d83fcaa8158c6683cb1/LICENSE)
and any individual source notices. The cache, ROMs, and reference images are not
committed or linked into the MIT-licensed VM. Redistributed test-result images
should retain attribution to that upstream revision.

The harness schedules 700 CHIP-8 instructions per second and 60 timer ticks per
second deterministically. Splash, IBM, Corax+, flags, and keypad results are
compared against independent reference framebuffers, after converting their
palette to monochrome. Corax+ and flags exclude the bottom-right version label.
The keypad scenario selects `Fx0A`, waits for the delay timer, then presses and
releases key A. The beep scenario verifies nine SOS pulses of
`10, 10, 10, 30, 30, 30, 10, 10, 10` timer frames and the PCM generator.

The quirks ROM selects CHIP-8 mode via RAM address `0x1FF`. Its six result
indicators are decoded separately: memory increment, shifting, and jumping pass;
VF reset, display wait, and clipping report the existing differences. Its
automated test preserves this explicit compatibility profile. Supporting those
remaining VIP quirks is a separate behavior change.

## Reports and scope

Each run saves scaled framebuffer PNGs and `timendus.json` under `tests/reports/`.
CI uploads them together with the built executable, including on test failure.
The images are generated by the VM; the reference inputs come from upstream.

These checks validate native instruction execution, interpreter state, callback
calling-convention behavior, and generated audio data. The Win32 message queue,
real GDI drawing, OS timer delivery, and audio-driver behavior are not emulated.
A Windows smoke test should open `ROMS/IBMLogo.ch8`, exercise keyboard input with
the keypad ROM, listen to the beep ROM, and close using both Esc and the window
close button. SUPER-CHIP/XO-CHIP scrolling is unsupported and is not tested.
